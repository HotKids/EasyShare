# 0.5 release draft

Unpublished draft. The application remains `0.4` (`versionCode = 4`). This
records the prepared source changes, not a published release or complete
physical-device acceptance.

## Transfer behavior

- Foreground reception uses the transfer half sheet. Background Accept and
  Decline do not bring the application to the foreground.
- The half sheet and live update coexist. Closing a sheet only hides it; one
  notification identity follows the request through progress and its result.
- Cancellation, timeout, and terminal states reject late progress updates.
  Progress remains below 100% until persistence; sending distinguishes a
  completion receipt from an unconfirmed result.
- Retain completed files after a partial cancellation and remove incomplete
  output. Archive path validation and transfer limits remain enforced.
- Open a single received file directly, or the task's captured directory for
  multiple files. Later save-location changes do not redirect older results.
- Persist result metadata and preserve terminal outcomes when reopening a
  result. Quiet readiness channels do not reset existing notification settings.

## Discovery and identity

- Handle routed Wi-Fi Direct connections where the system does not expose a
  matching ConnectivityManager network, and preserve actual peer addressing.
- Prefer explicit incoming identity, fresh matched BLE identity, then a verified
  remote group-owner model fallback. Unknown brands retain the Android icon.
- Preserve user-defined local device names and service-owned busy-state checks.

## Interface

- Keep six consistent Home settings rows with the approved grouping, dynamic
  hero colors, brand-tinted device card, Google artwork for Pixel, and copy.
- Improve brand and name editors, accessible controls, and radio/logo spacing.
- Use the Samsung-inspired central attachment layout, centered peer identity,
  equal text-button footers, clean discovery, and animated nearby search.
- Use official Material wavy progress inside the application and native system
  notification progress. Middle-ellipsis filenames preserve full-name access.
- Show received image previews and Close / Open result actions without an
  automatic result-dismiss timer.
- Include light fallback contrast, adaptive two-pane layouts, and the approved
  launcher artwork adjustment.

## Remaining release gates

- Verify physical send/receive, multi-file cancellation, notification lifecycle,
  peer identity, storage-provider behavior, process death, and accessibility.
- Validate adaptive layouts on the physical tablet.
- Obtain release approval before changing the version, pushing, or publishing.
  Existing signing and stored secure-transfer preferences remain unchanged.
